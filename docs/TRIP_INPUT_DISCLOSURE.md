# TRIP INPUT — 선택 완료 요약 및 세로 길이 개선

2026-10-25. 입력 UI만 변경. 기존 여행 데이터·저장 스키마·공식 자료·추천 로직은 변경하지 않음.

## 원인과 수정

- 선택 완료 후에도 국가6개 카드·검색창·도시 카드가 계속 남아 있었음.640px 이하에서 선택 완료 항목을 국가/도시 요약 행으로 표시하고 카드 목록은 공간을 차지하지 않도록 접음.
- ‘변경’은 기존 컨트롤을 다시 펼침. 선택값은 TripContext를 그대로 사용하며 접기 상태만 컴포넌트 임시 state로 관리. 다시 펼쳐도 선택값 유지. 다른 국가를 선택하면 기존 selectCountry 로직으로 도시 선택을 초기화.
- 모바일 검색으로 이동하거나 선택 완료 후 요약의 변경 버튼으로 포커스 이동. 선택 내용을 자동 삭제하지 않음.
- PC·태블릿에서는 같은 DOM의 기존 카드형 입력 유지. 폭을 모바일→PC→모바일로 바꿔도 선택 유지.
- 모바일에서 PACKING WORKSPACE 보조 문구와 TRIP SETUP 중복 설명을 숨기고 핵심 제목·로고·메뉴·START SCREEN 링크 유지.
- 국가/도시 카드는 좁은 화면에서 최소56px, 변경 버튼과 목적/수하물 선택은 최소44px. 기존 국가2열을 유지하며 목적/수하물은2열 Grid.
- 날짜 입력54px,480px 이하1열/그 이상2열과 공통 피드백 영역 유지. 안내를 ‘날짜를 선택하면 여행 기간을 계산해요.’로 간결하게 정리. 기존67.2px 피드백 최소 공간은 오류/기간 안내에 사용하며, 고정 높이로 본문을 자르지 않음.

## 390px 실측

Chrome viewport390×844, 일본·도쿄, 동일한 입력 상태. CSS 픽셀 기준.

| 측정 | 수정 전 | 수정 후 |
|---|---:|---:|
| 선택 전 페이지 높이 | 1,735 | 1,596 |
| 국가·도시 선택 완료 페이지 높이 | 1,891 | 1,204 |
| 선택 완료 입력 패널 높이 | 1,597.2 | 946.3 |
| 날짜 입력 시작 위치(문서 상단 기준) | 1,178.6 | 491.9 |
| 선택 완료 페이지의 최대 스크롤 거리(페이지 높이−844) | 1,047 | 360 |

선택 완료 페이지가687px(약36.3%) 줄었음. 수정 후 선택 전→선택 완료는1,596→1,204px. 최대 스크롤 거리는 동일 viewport의 기하학적 비교이며, 실제 손가락 스와이프 횟수나 사용성 실험 결과가 아님. 도시 수·문구·오류에 따라 높이는 달라짐.

PC·태블릿의 선택 완료 패널 높이는 수정 전후 동일:1440/1280px에서1,024.7px,1024px에서1,055.2px,768px에서1,359.5px.

- 선택 전/후/복원 DOM 치수·가로 넘침 검사, 모바일 요약2개와 PC 카드 표시, 국가/도시 변경·기존 선택 보존·국가 변경 시 도시 초기화·국가/도시 검색·포커스·44px 터치 영역.
- 날짜·여행 목적·수하물 입력→MY BAG 생성→여행 정보 변경→입력값 복원 및 새로고침 후 보존.390px에서PC1440px로 확장했다가 돌아와도 선택 보존.

- 단위 테스트94개 통과. TypeScript·Vite 프로덕션 빌드 통과.
- 테스트 작성 중 reload 완료 이전의 이전 DOM을 읽는 경합을 수정하고 최종 검사를 처음부터 재실행. 서비스 오류로 집계하지 않음.

증거: [변경 전](verification/trip-disclosure/before.json), [변경 후](verification/trip-disclosure/after.json), 같은 폴더의 before/after 캡처.390px 선택 완료 캡처를 직접 확인. OS 네이티브 달력·실제 iOS/Android 기기·실사용자 입력 시간은 미검증. 이번에 전체 국가 규정을 재검증한 것은 아님.
