# 날씨 카드 개선 및 기후 데이터 점검

점검일: 2026-10-25

## 공통 카드 디자인

- 월별 `N월 평균기온` 라벨과 수치를 별도 줄로 표시. PC 14px / 34px, 모바일 13px / 30px. 수치는 700 굵기.
- 옷차림 추천 14px. 제목·아이콘·연한 블루 배경·상세 모달과 하단 링크 유지.
- 여러 달은 월별 묶음으로 줄바꿈. 미수집 상태는 16px 안내로 표시. 호주 계산 참고 표시 유지.
- 모든 국가가 동일한 TripBrief 컴포넌트를 사용하며 기후 데이터와 계산 로직은 수정하지 않음.

## 저장 데이터와 연결 현황

전체 17개 도시 × 12개월의 getClimateMonth 반환값을 확인했다.

| 국가 | 도시 | 평균기온 가용 월 |
| --- | --- | --- |
| 일본 | 도쿄, 오사카, 후쿠오카, 삿포로 | 각각 12/12 |
| 미국 | 뉴욕, 로스앤젤레스 | 각각 12/12 |
| 호주 | 시드니, 멜버른 | 각각 12/12 |
| 태국 | 방콕, 푸껫, 치앙마이 | 각각 0/12 |
| 베트남 | 다낭, 하노이, 나트랑, 푸꾸옥 | 각각 0/12 |
| 대만 | 타이베이, 가오슝 | 각각 0/12 |

기후 조회 경로(src/service/data/climate.ts)는 호주·미국 조회 후 일본 관측소를 확인한다. 그 외 도시는 recommendedMetrics: null, status: needs-research를 반환한다. 프로젝트의 검증된 수치·원본 자료는 일본 JMA, 미국 NOAA/NWS, 호주 BOM 범위이며 태국·베트남·대만의 검증된 월별 수치가 저장된 별도 데이터셋은 발견되지 않았다. 도시 목록에는 존재하지만 기후 데이터셋이 미구축된 상태로, 기존 수치의 연결 오류는 아니다. 이는 프로젝트 내 수집 현황이며 해당 국가에 공식 기후 자료 자체가 없다는 뜻은 아니다.

일본은 최근 10년 관측 평균과 항목별 공식 평년값 대체 정책, 미국은 1991–2020 평년값, 호주는 공식 최고·최저의 중간값 계산 참고를 그대로 사용한다. 임의 수치나 타국 자료 대체, 외부 API 추가는 없다.

## 검증

- TypeScript 및 Vite 프로덕션 빌드 통과.
- 기존 테스트 57개 통과(기후 출처·원본, 월별 계산, 옷차림, 체크리스트 등).
- 실제 TripBrief 서버 렌더링과 해당 CSS를 Chrome headless에서 측정. 오사카 단일 월, 방콕 누락 상태, 시드니 두 달 사례 확인. 모달은 렌더링 점검 대상에서 제외.
- PC 콘텐츠 폭 1210px에서 세 카드 높이 모두 194px. 수치 34px, 가로 넘침 없음.
- 모바일 CSS에서 수치 30px, 세로 카드 배치 유지. 좁은 272px 콘텐츠 폭에서도 가로 넘침 없음. 모바일은 기존처럼 콘텐츠에 맞는 개별 높이를 사용하며 불필요한 동일 높이 강제는 하지 않음.
- 이 검증은 독립 카드 렌더링 측정이며 전체 MY BAG 화면의 수동 시각 검수는 포함하지 않음.
